# CRAB · страница «Позиции» — README для верстальщика

Прототип: `crab-dashboard-variants.html` (рабочий файл, один экран, без сборки и зависимостей).
`crab-dashboard-standalone.html` и `index.html` — тот же файл, обёрнутый в `<!doctype html>` (standalone для раздачи, index для GitHub Pages). Живое демо: https://serjnsk.github.io/crab-dashboard-design/

Прототип — источник спецификации: токены, размеры, пороги, поведение. DOM и JS из него не переносится как есть.

---

## 1. Что в прототипе демо-специфично (НЕ верстать)

- Блок «уплотнение истории» в JS: генерирует 17 срезов к 8 ручным (итого 25), интерполяция позиций с шумом. В продакшене срезы приходят с бэка.
- Дубли групп «… · 2/3/4» — созданы для проверки sticky на длинной прокрутке.
- Детерминированные генераторы: динамика частотности (`k.wsd/k.wsed`), реклама по срезам (`k.adsAt`), позиции доп. URL (`ourUrlsFor`), выдача SERP (`serpForDate`, перестановки по seed), «старая страница» в попапе смены релеванта. Всё это — данные API.
- Хвосты вариантов дизайна: CSS-классы `.v2….v13`, легаси-хелперы (`renderSummaryTable`, `summary-strip/cards/chart`, `serpListHtml`, `nowCellHtml`, `renderDetail`, `detail-rail`) — не используются, финальный вариант один (`v15`, cells-fill).
- Переключение вариантов/тем в правом нижнем углу — служебное.
- Даты окончания регистрации и регистраторы доменов на главной (`exp`, `reg` у проектов в `HOME`) — демо, отсчёт от `PJ_TODAY`.
- Дашборд проекта и страницы источников (раздел 14): ряды Метрики/GA4/GSC/Вебмастера генерируются от домена (`pjSeries`, `pjLevel`, `pjSteps`), «сегодня» — `PJ_TODAY`; какие источники подключены — по ПС мониторингов проекта; лог, команда, заметки, аккаунты подключений, «Обновлено N назад», история PageSpeed по страницам (`pjPsiPage`), строки таблиц (`pjGscRows`, `pjMetrikaRows`, `pjGaRows`), значения и проблемы Вебмастера (`pjWmProbs`, `pjWmKeys`; набор полей — как в API v4), «Проверка URL» и Sitemap — демо. «Опросить» в прототипе только меняет подпись на «только что»; «Настройки подключения», «Подключить», «Управлять доступами», ⚙ мониторинга — без действия.
- Ассистент (раздел 13): ответы собираются в браузере из демо-данных (`aiCompose`, `aiAns*`), «стриминг» — нарезка готового HTML по словам (`aiGenerate`), история чатов — сиды (`aiSeed`), кредиты за ответ и список моделей (`AI_MODELS`) — заглушки. Блок «Демо-состояния» внизу истории чатов — служебный. В продакшене ответы, шаги и списания приходят с бэка.

## 2. Токены и темы

- Все цвета — CSS-переменные в `:root` (строки ~4–62): `--accent`, `--bg/--surface/--surface-2`, `--border/-strong`, `--row-group` (полоса группы на главной: светлая `#E4E8EE`, тёмная `#262E3B`), `--text/-2/-3`, пороги позиций `--t3/t10/t20/t50/t100` (по три: `-bg` заливка, `-fg` текст, `-heat` насыщенный), `--up/--down`, типизация `--typ-*`.
- Тёмная тема: те же переменные в `@media (prefers-color-scheme: dark)` + принудительно через `:root[data-theme="light|dark"]` (переключатель в шапке: system/light/dark).
- В тёмной теме `--t*-bg` полупрозрачные (rgba) — для липких ячеек нужна непрозрачная подложка: `background: linear-gradient(var(--t100-bg),var(--t100-bg)) var(--surface)`.
- Шрифты: системный стек (`--sans`), моно для чисел частотности (`--mono`), табличные цифры `font-variant-numeric: tabular-nums` везде в данных.

## 3. Каркас

- Топбар: высота 52px, `position:sticky; top:0; z-index:40`.
- Сайднав: 64px, `sticky; top:52px; height:calc(100vh−52px); z-index:30` (выше липких строк таблицы — флайаут мониторингов не перекрывается).
- z-index шкала: строки таблицы 2–5 → шапка таблицы 10–11 → сайднав 30 → панель ассистента 35 (на <900px — 90) → топбар 40 → hsb (плавающий скроллбар) 60 → дропдауны 70 → поиск 80 → попапы (swap/kuPop/typMenu, меню ячейки `#aiCellMenu`) 95–120 → модалки 95–96 → меню юзера 110.
- Панель ассистента справа (раздел 13) при ≥900px не перекрывает контент, а сужает его: `.shell` получает `padding-right` = ширина панели + 6px зазора рамы.

## 4. Таблица позиций — адаптивность (главное)

Фиксированная левая часть: КЛЮЧ 240–340px + ТОП-10 86 + SERP 60 + ЧАСТОТНОСТЬ ~110 ≈ 490–500px.
Ширина колонки среза = (ширина контейнера − левая часть) / число срезов. Ступени:

1. **≥ 62px — полная**: позиция + дельта, дата «дд.мм» + день недели (+ время при наличии).
2. **< 62px — компакт `sl-mid`**: min-width 44px, паддинг 0 2px; позиция и дельта остаются всегда; в шапке только «дд.мм»; дельты в сводке скрываются; полные данные в title.
3. **Не влезло — `kw-clamp`**: КЛЮЧ зажимается ровно до 240px. Влезло — стоп (скролл не включаем, вертикальные sticky живы).
4. **Всё равно не влезло — `h-scroll`**: горизонтальный скролл контейнера таблицы.

**Дельты изменений не сворачиваются ни на одной ступени.**

Скролл-режим (`h-scroll`):
- Sticky left: КЛЮЧ 0 / ТОП-10 240 / SERP 326 / ЧАСТОТНОСТЬ 386. Sticky right: последний срез. Фоны липких ячеек непрозрачные.
- Старт прокрутки — у последних срезов (`scrollLeft = max`).
- Тени на краях: классы `sc-left` (scrollLeft > 2) / `sc-right` (< max−2).
- ⚠ Вертикальный sticky внутри скролл-контейнера отсчитывается от контейнера, не от окна: для thead и шапок групп в этом режиме `top:auto` (иначе шапка съезжает вниз на величину top).
- Родной скроллбар контейнера скрыт; вместо него плавающая полоса `.hsb` `position:fixed` у нижней кромки окна: left/width по контейнеру, двусторонняя синхронизация scrollLeft, видна пока таблица в вьюпорте, у конца таблицы прижимается к её нижней границе (`bottom = max(0, innerHeight − rect.bottom)`).

Пересчёт (`applySliceDensity`):
- Триггеры: рендер, resize (debounce 120мс), смена числа срезов/периода.
- ⚠ Перед измерением снять ВСЕ классы адаптации (`sl-mid`, `kw-clamp`, `h-scroll`) — иначе гистерезис: зажатый КЛЮЧ искажает ширину и решение «нужен ли скролл» становится нестабильным.
- scrollWidth читать синхронно после установки классов; ⚠ не использовать rAF — не срабатывает в фоновых вкладках.
- Высота thead переменная (время в датах, компакт) — мерить фактическую → `--thead-h`; липкие шапки групп: `top: calc(52px + var(--thead-h))`.

Сводка живёт в той же колоночной сетке (первый tbody) — ступени применяются автоматически.

## 5. Ячейка позиции

- `.cell` — кнопка на всю ячейку (cells-fill: заливка цветом порога `--t*-bg` + текст `--t*-fg`), клик открывает SERP-модалку.
- Дельта — «степенью» сверху справа: 9.5px, 700, `--up/--down`; знак у отрицательных из числа.
- Маркеры — колонкой у правого края ПОСЛЕ позиции: ⇅ сверху, реклама (SVG-логотип Google Ads) снизу; круглые бейджи 16px (14px в компакте) с подложкой `--surface` и рамкой; пара центрируется по вертикали, одиночный — по центру; hover ⇅ — scale(1.12).
- ⇅ кликабелен → попап «Смена релевантной страницы»: Было/Стало, URL+тайтл, у каждого копирование и переход; позиционирование у иконки, переворот вверх при нехватке места.
- «—» вне ТОП-100, «н/д» позиция не снята (пунктирная рамка).
- title ячейки: дата, позиция, дельта.

## 6. Колонка КЛЮЧ

- Иконка ПС — ссылка `https://yandex.ru/search/?text=<encoded kw>`, `target=_blank`.
- Клик по тексту ключа или иконке копирования (появляется на hover строки, 18px) — копирование в буфер; фидбек: галочка `--up` 1.2с; фолбэк `execCommand('copy')`.
- Релевантная страница: строка «≠ /path/» под ключом; если сайт в выдаче несколькими URL — рядом чип «N URL ▾» → попап `kuPop`: все URL с актуальными позициями последнего среза, позиции подсвечены порогами.

## 7. Частотность

- Показывается ОДИН вид: переключатель «базовая | !точная» в шапке колонки (сегмент как «123/%» в сводке). Для Google — один вид, переключателя нет.
- Формат: ≥1000 → `1,3k`, ≥1e6 → `1,2M`; точная с оранжевым префиксом `!`.
- Дельта к прошлому месяцу — «степенью», формат тот же (`+12,3k`); полное число в title. Месяцы — `WS_MONTH`/`WS_PREV`.

## 8. SERP-модалка

- Шапка: ПС + ключ + крестик; период (общий календарный компонент: диапазон + частота) + пресеты «Последние 5/10» (active — когда набор совпадает). Чипов отдельных дат нет: диапазон+частота определяют показанные срезы.
- Колонки по 310px; ОДИН срез — колонка 600px по центру (ширина результатов Google), на узких экранах `min(600px, 92vw)`.
- **Одна общая вертикальная прокрутка** на все колонки (`.sm-cols{overflow:auto}`), шапки колонок sticky top:0.
- **Фиксированные высоты** — позиции разных дат не разъезжаются: шапка колонки 38px, полоса рекламы 30px (есть во ВСЕХ колонках; без рекламы — заглушка «Без рекламы в выдаче»), строка результата 74px (тайтл клампится на 2 строки).
- Строка: маленький номер позиции 17px с цветом типизации → фавиконка 19px (акцент) в строке тайтла → тайтл → строка URL. Фавиконка двухслойная: цветная буква-заглушка (hsl от hash домена) мгновенно + реальная `google.com/s2/favicons?domain=…&sz=32` поверх после onload.
- Наш сайт: только красная вертикальная черта слева 3px, без заливки и меток.
- ТОП-10 по умолчанию; если наша позиция 11–20 — ТОП-20.
- Кросс-подсветка: hover по строке подсвечивает этот домен во всех колонках (класс `hl`, фон `--t3-bg`).
- ПКМ по строке — меню «Категория сайта»: пункты из настроек типизации с цветными точками, галочка у текущей, выбор перекрашивает бейджи домена во всех колонках; внизу «Настроить категории…».
- Числа позиций «наша позиция» в шапке колонки — бейдж с цветом порога.

## 9. Прочие компоненты

- Календарь периода: открывается ПОД своей кнопкой, правым краем к ней; прижим к краям окна, переворот вверх при нехватке места; общий для тулбара и модалки (в модалке — fixed, чтобы не резался overflow).
- «Позиции конкурента»: модалка 400px с затемнением — поле адреса (автофокус), «Показать позиции» (primary) / «Отмена»; пустое поле — красная рамка; Enter/Escape/бекдроп.
- Меню юзера (hover по аватару): шапка имя+почта, строка «Команда», две плитки-счётчика (видит проектов / создал), секции «Аккаунт»/«Данные» с иконками, красный «Выйти». Тарифов и лимитов нет.
- Флаги регионов — SVG (эмодзи-флаги не рендерятся на Windows): в статусах заголовка и после названий супергрупп, 17×12, тултип с регионом.
- «Перейти к группе» — дропдаун с поиском, скроллом к группе и подсветкой-вспышкой.
- Все оверлеи закрываются: клик вне, Escape; одновременно открыт максимум один.
- Срок регистрации домена (главная, строка проекта): иконка 17px — размер фавиконки `.pfav` — сразу за ссылкой на сайт `.p-link`, зазор ~6px. Сама скрепка — как в боевом интерфейсе: цвет текста, без прозрачности, ~13px от имени; при добавлении иконки её стиль не меняется (`domExpHtml`, класс `.dom-exp`). Подсказка — плавающий слой в `body` (`dexpShow`): CSS-тултип внутри sticky-ячейки имени перекрывается следующей строкой. В подсказке заголовок (ниже), «Дата окончания» и «Регистратор» (данные WHOIS/RDAP); под иконкой, у нижнего края окна — над ней. Жёлтая с часами — до окончания 7–1 день, заголовок «Через N дней истечёт срок регистрации домена»; красная с «!» — день в день, «Сегодня истекает срок регистрации домена»; просрочен (после даты) — другая фигура, залитая красная голова-«труп» с глазами-крестиками и языком (`DOMEXP_DEAD`), «Срок регистрации домена истёк N дней назад»; больше 7 дней или даты нет — иконки нет. Цвет — токены `--dexp-*` (обе темы), клик по иконке не сворачивает проект. Исходники и правила — стикерпак `icons/` (`<base>/icons/`).

## 10. Брейкпоинты

- ≥1200px: таблица без скролл-контейнера (sticky живут), кроме принудительного `h-scroll`.
- <1200px: контейнер `overflow-x:auto`, вертикальные sticky таблицы отключены (`top:auto`).
- <900px: мобильный паттерн (спарклайн вместо колонок срезов) — в прототипе НЕ реализован, только описан.
- Открыт ассистент: пороги по ширине окна для этой страницы не меняются — плотность срезов и скролл считаются по фактической ширине контейнера (`applySliceDensity`). В продакшене пересчёт привязать к `ResizeObserver` контейнера таблицы, а не к `resize` окна: открытие панели окно не меняет.

## 11. Что подключается к API (сейчас захардкожено/генерится)

срезы и позиции; частотности обоих видов + их дельты и месяц данных; события смены релеванта (старый/новый URL+тайтл); признак рекламы и число объявлений по срезу; выдача ТОП-10/20 с тайтлами/URL/типизацией; все URL сайта по ключу с позициями; категории типизации проекта (названия/цвета); команда и счётчики проектов юзера; регионы супергрупп; дата окончания регистрации домена проекта и регистратор (WHOIS/RDAP); фавиконки (сервис или свой прокси); ассистент — чаты аккаунта, ответы (SSE), шаги-вызовы функций, модели и списания кредитов (раздел 13).

## 12. Стоимость мониторингов (`<base>/costs`, только админы)

Вход: меню профиля → «Администрирование» → «Стоимость мониторингов».

- **Источник — отдельные сборы** (мониторинг × дата × тип): время, проект, мониторинг, команда, владелец, ПС (`Yandex/Google Desktop/Mobile`), тип (`Позиции` / `Частотность`), глубина (у частотности нет), ключи, парсер, сумма по тарифу, валюта, курс, сумма в ₽. В прототипе их генерирует `COST_RUNS` по расписаниям мониторингов главной (демо, с 01.07.2026), в продакшене они приходят с бэка.
- **Валюта:** все итоги в ₽. Сборы в $ пересчитываются по курсу на дату сбора, курс хранится в самом сборе. Исходная сумма в $ и курс показываются мелко под суммой сбора.
- **Период:** любой диапазон: пресеты (сегодня, вчера, 7 и 30 дней, этот и прошлый месяц, квартал, всё время) и два месяца календаря.
- **Группировка — 2 уровня.** Измерения: Команда, Владелец, Проект, Мониторинг, ПС, Парсер, Тип, Глубина. Второй уровень можно отключить. Раскрытие: 1-й уровень (светлая полоса с кромкой сверху) → 2-й уровень (светлая полоса с графитовой кромкой, как проект) → сборы, по 25 штук с кнопкой «Показать ещё».
- **Колонки:** ПС, Тип, Глубина, Парсер, Владелец. В строке группы значение показывается, только если оно одинаково у всех её сборов. Метрики: Мониторингов (сколько раз мониторинги запускались за период; в строке сбора пусто), Запросов (ключи × запуски), ₽/1000, Доля от итога, Стоимость. Сортировка по клику на заголовок применяется на всех уровнях; «по имени» для сборов означает хронологию.
- **Фильтры** (мультивыбор, панель не закрывается при клике): Команда, Владелец, ПС, Парсер, Тип + поиск по мониторингу или проекту. Есть «Сбросить».
- **CSV** — плоский список сборов с учётом периода и фильтров (`;`, UTF-8 BOM).
- «Настроить цены» — пока просто кнопка. Тарифы в прототипе лежат в `C_PRICE`.
- **Ширина:** таблица `table-layout:fixed`, `min-width:1340px`; уже этого включается горизонтальный скролл.

## 13. Ассистент (AI-чат в правом сайдбаре)

Чат с нейросетью по данным проекта. Чаты общие для аккаунта; у чата есть контекст — мониторинг(и). Модели — через агрегатор kie.ai.

**Точки входа**
- Кнопка «Ассистент» в топбаре (иконка-искра + подпись; <1100px — только иконка), `aria-expanded`. Горячая клавиша ⌘J / Ctrl+J. Красная точка на кнопке — ответ дописался, пока панель была закрыта.
- Строка ключа: на hover рядом с копированием — иконка-искра «Спросить ассистента о ключе».
- Правый клик по ячейке позиции — меню «Открыть ТОП выдачи» / «Спросить ассистента о позиции» (ключ + дата + позиция).

**Раскладка**
- ≥900px: `position:fixed; top:52px; right:0; bottom:0`, ширина 400px, развёрнутая — `clamp(400px, 100vw − 624px, 640px)`. Контент сужается (`.shell{padding-right}`), между ним и панелью — 6px графитовой рамы; у обеих карточек скругление 14px сверху. Плотность срезов пересчитывается при открытии, закрытии и смене ширины.
- <900px: на весь экран — `100vw × 100dvh` (не по layout viewport, иначе fixed-панель тянется вслед за широкой страницей), z-index 90, кнопки 40–44px, поле ввода 16px (iOS не зумит).
- Главная с открытой панелью: те же ступени ширины колонок, что по ширине окна, сдвинутые на ширину панели (+406 / +646px); колонка имени забирает остаток; если всё равно не влезло — горизонтальный скролл (`.ai-ovf`); подписи групп обрезаются многоточием.
- Открыта / развёрнута / модель — в localStorage (`crab-ai-ui`); восстанавливается ДО первого рендера, чтобы первая раскладка таблицы считалась уже с панелью.

**Поведение**
- Панель — не оверлей: клик мимо её не закрывает, SERP-модалка открывается поверх, чат остаётся. Esc закрывает панель, только если фокус в ней и поверх нет модалки или попапа (первый Esc закрывает модалку). После закрытия фокус — на кнопку в топбаре.
- Переходы между страницами: пустой чат подхватывает мониторинг открытой страницы. Если в чате уже есть сообщения, а открыт другой мониторинг — над полем плашка «Сейчас открыт мониторинг «B»…» с кнопками «Новый чат по «B»» (primary) и «Добавить в этот».

**Шапка**: слева — заголовок чата (из первого вопроса) + подстрока «ПС · мониторинг · домен» или «Весь аккаунт»; справа иконки: «История чатов» (список) · «Новый чат» (плюс; неактивна, пока открыт пустой чат) · «Расширить / Сузить» · «Закрыть».

**Пустой чат**: иконка, заголовок по контексту (мониторинг / ключ / весь аккаунт) и одна строка о том, что видит ассистент. Вопросов-подсказок в пустом чате нет.

**Сообщения**
- Вопрос — пузырь справа; над ним чипы контекста (ключ · дата · позиция, скриншот).
- Ответ — без пузыря: шаги → текст → строка действий.
- Шаги = вызовы функций к данным CRAB. Во время работы — список со спиннером на текущем; после — свёрнутая строка «Посмотрел данные · N шагов», раскрывается по клику.
- Ссылки на данные: ключ (чип с иконкой-мишенью) → скролл к строке таблицы + вспышка (раскрывает свёрнутые группы, сбрасывает вкладку-фильтр); позиция (бейдж цвета порога) → SERP-модалка на эту дату; группа → строка группы; мониторинг → его страница. Если чат про другой мониторинг — сначала переход на него. На <900px после перехода панель закрывается.
- В ответе бывают мини-таблицы (ключ · было · стало), спарклайн позиций ключа и подсказки следующего вопроса (несут контекст ключа).
- Под ответом: копировать · ответить заново (только у последнего) · 👍 / 👎 · справа «Модель · N кр.» — списание kie.ai за ответ.
- Счёт в ответах — как во вкладках таблицы (по строкам): «просели 32» совпадает с вкладкой «Упавшие 32».

**Состояния ответа**: в очереди (лимит kie.ai по документации — 20 новых запросов за 10 с на аккаунт, уточнить для чата) → шаги → печать с курсором → готово. «Стоп» — на месте кнопки отправки; остановленный ответ помечается «Ответ остановлен». Ошибка модели — красная плашка «Повторить» / «Сменить модель». Кредиты закончились — жёлтая плашка над полем, ввод заблокирован, история доступна.

**Поле ввода**: чипы контекста (до первого сообщения — мониторинг, убирается ×; ключ и скриншот — к следующему вопросу), textarea с авторостом до 168px, Enter — отправить, Shift+Enter — перенос строки. Ниже: скрепка (активна только у моделей со скриншотами), выбор модели (поповер вверх: курируемый список, отметка «по умолчанию», описание), круглая кнопка отправить/стоп. Подпись под полем: «Ассистент может ошибаться — проверяйте цифры по ссылкам в ответе».

**История чатов**: поиск; группы «Сегодня / Вчера / На этой неделе / Ранее»; строка — заголовок, ПС и мониторинг (или «Весь аккаунт»), время; если последний ответ с ошибкой — «нет ответа». Пустые черновики в историю не попадают.

**Бэкенд (в прототипе нет)**
- У семейств моделей в kie.ai разные форматы API (Gemini — Chat Completions, Claude — Anthropic Messages, GPT/Grok/DeepSeek — Responses) → нужен свой адаптер и хранение истории в нейтральном формате, иначе модель посреди чата не сменить.
- Мониторинг целиком в запрос не помещается: на старте — сводка мониторинга, детали ассистент получает через функции (позиции ключей за период, выдача на дату, смены релеванта, частотность). Каждая функция = строка в «шагах».
- Ошибки kie.ai могут приходить с HTTP 200 и кодом в теле (например, 402 — нет кредитов) — разбирать тело ответа.
- Список моделей и флаг «принимает скриншоты» — конфиг на бэке (в прототипе `AI_MODELS`), в списке только модели, проверенные на функциях CRAB.

## 14. Дашборд проекта (`<base>/projects/<ID_PROJECT>`) и страницы источников (`…/gsc`, `…/metrika`, `…/ga`)

Вход на дашборд: имя проекта на главной (остальная часть строки проекта по-прежнему сворачивает его), «Проект» в сайдбаре и домен в крошках страницы позиций. В сайдбаре активен «Проект», флайаут «Позиции» — реальные мониторинги проекта.

**Крошки и шапка**: «Проекты / <группа> / <проект>» (у проекта без группы — «Проекты / <проект>»); клик по группе — главная, прокрутка к строке группы (свёрнутая раскрывается) и короткая подсветка. Так же устроены крошки страницы позиций и подробных страниц источников. Шапка: фавиконка, H1 = переключатель проекта (дропдаун по группам), ссылка на сайт; строки меты под названием нет — владелец в «Команде», мониторинги и ключи в «Мониторингах», PageSpeed в своём блоке. Действия: «Настройки проекта», primary «+ Новый мониторинг».

**Без лишних подписей**: у модулей нет подзаголовков-пояснений; «без изменений» под цифрами — короткое «—» (расшифровка в подсказке), «нет данных» — так же. Широкая карточка мониторингов (≥760px) растягивает колонки цифр пропорционально, имени остаётся около трети ширины.

**Раскладка — без дыр при любом наполнении.** Карточки одного ряда всегда одной высоты, фон страницы между ними не просвечивает. Верх — две равные колонки: слева **Мониторинги** и под ними **Команда проекта** (последняя карточка колонки тянется, «Управлять доступами» прижата к низу), справа **Лог проекта** — его высоту задаёт левая колонка, а не число событий. **Первым блоком** страницы идёт компактный **Google PageSpeed** на всю ширину (подключение не нужно — PSI API работает с ключом сервера), за ним — этот верхний ряд, ниже без заголовка секции — подключённые источники парами в порядке Метрика | GA4, Вебмастер | GSC (Яндекс слева, Google справа); если пары нет — карточка на всю ширину. **Период общий для страницы, а выбор — внутри каждого блока**: кнопка с датами окна «📅 20 июня – 19 июля ▼» (у виджетов — в начале строки «обновлено…», у PageSpeed — в шапке) открывает список 7 дней / 30 дней / 90 дней / 12 месяцев с пояснением «Период общий для всех блоков страницы. Изменения — к предыдущему периоду такой же длины»; смена в любом блоке перерисовывает все. Даты кнопки учитывают задержку данных источника (GSC −2 дня, Вебмастер −3), поэтому у разных блоков они немного различаются. Подробные страницы источников используют тот же период. Неподключённые и отозванные источники — компактная полоса над сеткой («Не подключено» → «Подключить», «Нет доступа с …» → «Переподключить»), а не пустые карточки во всю высоту ряда. Нижняя таблица каждого виджета — «заполнитель»: минимум 7 строк (у Вебмастера 5), а если соседняя карточка выше — показывает столько строк, сколько целиком помещается (пересчёт по `ResizeObserver`). Контейнер `.pj-wrap` ≤1060px (например, с открытым ассистентом) → всё в одну колонку.

**Мониторинги** — логика строки как на главной: ☆ избранное (общее с главной) и ⚙ настройки; имя с ПС и регионом, под ним статус (точка + текст) и дата следующего среза (расписание — в подсказке); «Позиции ключей» ТОП 1–3 / 1–10 / 11–20 / 21–50 / 51–100 — число и под ним изменение к прошлому срезу (как надстрочные дельты главной, но не мельче 11px); Ключи; URLs; Видимость (доля ТОП-10, изменение в п.п.). Строка — ссылка на страницу позиций (клик, Enter). Колонки фиксированной ширины, имя забирает остаток и обрезается многоточием (полное — в подсказке). Карточка ≤600px (окно ~1280px) → колонка URLs схлопывается до нуля (не `display:none` у ячеек — это сдвигает колонки); уже 520px — горизонтальный скролл внутри карточки.

**Виджет источника (Метрика, GA4, GSC)** — по образцу «Завода»:
- Шапка: иконка, название (кнопка → подробная страница), «ресурс · аккаунт подключения», зелёный щит «Подключено», «Подробнее →» (тоже на подробную страницу).
- Строка «📅 период ▼ · обновлено N назад · задержка» + «Опросить» (запрос свежих данных: иконка крутится, потом «обновлено только что»; при Reduce Motion без вращения). Заметок в виджетах нет — переключатель «Заметки N» (заметки команды: пунктирные вертикали и маркеры на оси X, текст с автором в тултипе точки) только на подробной странице.
- KPI-пилюли: подпись, значение, дельта к прошлому периоду. Выбранная пилюля залита `--pill-sel` (светлая `#226cc8`, тёмная `#2f74d0` — белый текст ≥4.5:1) и задаёт метрику графика; выбор общий с подробной страницей.
  - Метрика: Визиты · Из поиска (+доля) · Отказы (меньше = лучше) · Время на сайте.
  - GA4: Сеансы · Organic Search (+доля) · Вовлечённость · Время вовлечения.
  - GSC: Клики · Показы · CTR · Позиция (ось перевёрнута — выше лучше, без заливки).
- График одной серии (слот `--ch-1`): плавная монотонная кривая (без выбросов за пределы данных), заливка градиентом. У Метрики и GA4 последний отрезок пунктиром — период ещё идёт, в тултипе «данные неполные».
- Топ-таблица за период (заполняет остаток высоты карточки, см. «Раскладка») и ссылка «Все запросы / Все страницы · N →» на нужную вкладку подробной страницы. GSC: Ключ · Показы · Клики · Позиция · ГЕО (ISO-3); Метрика: Страница · Визиты · Отказы · Время; GA4: Страница · Сеансы · Вовлечённость · Время.
- Полос долей источников/каналов больше нет — эти данные на подробной странице во вкладках «Источники» / «Каналы».

**Яндекс Вебмастер** — ошибки и ключи, без графика трафика; только поля, которые отдаёт API Вебмастера v4 (сверено со справочником yandex.ru/dev/webmaster). Шапка как у виджетов, «Открыть ↗» ведёт во внешний Вебмастер (своей подробной страницы нет).
- Сводка (KPI): ИКС (`summary.sqi`, дельта — `sqi-history`) · Страниц в поиске (`summary.searchable_pages_count`, дельта — `search-urls/in-search/history`) · Исключено (`summary.excluded_pages_count`; «из них N за период» — сумма `REMOVED_FROM_SEARCH` из `search-urls/events/history`) · Битые ссылки (`links/internal/broken/history`, сумма индикаторов на последнюю дату, рост = плохо).
- «Ошибки сайта»: чипы Фатальные / Критичные / Возможные / Рекомендации — числа из `summary.site_problems`; клик фильтрует список (повторный снимает; по умолчанию все, кроме рекомендаций; пустые — disabled). Список — `diagnostics`, только `state = PRESENT`: заголовок по коду `ApiSiteProblemTypeEnum` (тексты из справочника, код — в подсказке), текст важности (не только цвет), «с <last_state_update>», бейдж «новая» за последние 7 дней; первые 3 + «Ещё N в Вебмастере». **Количества страниц и деталей проблемы API не отдаёт** — их не показываем, подробности по ссылке в Вебмастер. Строка «Ошибки при обходе за период: 4xx · 5xx · нет ответа и др.» — суммы `HTTP_4XX` / `HTTP_5XX` / `OTHER` из `indexing/history`.
- «Ключи в Яндексе» (`query-analytics/list`): Запросов с показами (`count` с фильтром `IMPRESSIONS > 0` за период) · В ТОП-3 и В ТОП-10 (`count` с фильтром `POSITION ≤ 3 / ≤ 10`) · Ср. позиция показа (`AVG_SHOW_POSITION` из `search-queries/all/history`); все — с дельтой к прошлому периоду (второй запрос за предыдущий период). Вкладки Все / Выросли N / Упали N; таблица Запрос · Спрос (`DEMAND`) · Показы (`IMPRESSIONS`) · Позиция (`POSITION`, бейдж цвета диапазона) · Изм. (позиция в начале и в конце периода по дневной статистике, ▲/▼ на сколько позиций) — заполнитель, минимум 5 строк.

**Google PageSpeed — компактно, с выбором страницы** (≈230px высотой).
- Шапка одной строкой: иконка, «Google PageSpeed», выбор страницы «Страница: Главная ▼» (по умолчанию главная; в списке — главная и релевантные URL проекта, до 12, у каждой текущая Performance на выбранном устройстве со статусом), переключатель Mobile / Desktop (по умолчанию Mobile, как в PSI), период блока «📅 даты ▼», «проверено сегодня в HH:MM», «Проверить» (внеочередной запуск PSI для выбранной страницы), «PageSpeed Insights ↗» (открывает выбранную страницу).
- 4 плитки — Performance / Accessibility / Best Practices / SEO: оценка со статусом (цвет по порогам Lighthouse 90 / 50 + форма ● ■ ▲), изменение к предыдущему периоду и мини-график за период (по дням; 12 месяцев — по неделям) без осей: линия, заливка, пунктир порога 90 (всегда в кадре, если оценка ≥70), тултип с датой и значением при наведении и с клавиатуры. Шкала мини-графика — по данным, но не выше 100 и не уже 12 баллов, чтобы ровный ряд не превращался в «пилу». Карточка ≤720px → плитки 2×2.
- Строка «Метрики · Mobile/Desktop»: LCP, TBT, CLS, FCP, Speed Index — значение, форма статуса по порогам Core Web Vitals (LCP 2,5 / 4 с; TBT 200 / 600 мс; CLS 0,1 / 0,25; FCP 1,8 / 3 с; SI 3,4 / 5,8 с; полные названия и пороги — в подсказке) и изменение (меньше = лучше).
- История — данные CRAB: PSI API отдаёт только текущий прогон (`lighthouseResult.categories.*.score` и `audits` метрик), поэтому сервер раз в сутки запускает проверку каждой страницы с `strategy=mobile` и `strategy=desktop` и хранит результаты.

**Состояния источника**: на дашборде — полоса над сеткой («Не подключено» / «Нет доступа с <дата>», красная рамка и иконка); на подробной странице — пустое состояние с кнопкой «Подключить» / «Переподключить».

**Лог проекта**: фильтр Все / Мониторинги / Настройки / Доступы / Интеграции, группировка по дням (заголовок дня липнет к верху при прокрутке), «было → стало», имена мониторингов — ссылки с иконкой ПС. Событий может быть и 5, и 50 — высоту карточки задаёт соседняя колонка, лента прокручивается внутри (минимум 300px, в одну колонку — 440px); внизу закреплена строка с числом событий, у нижнего края ленты — затемнение, пока есть что листать. **Команда проекта**: владелец, пользователи и команды с уровнем доступа, «Управлять доступами».

**Подробная страница источника** (`<base>/projects/<ID>/gsc | metrika | ga`; вход — название виджета, «Подробнее», «Все … →»):
- Крошки «Проекты / домен / источник», заголовок с иконкой и «Подключено», мета: ресурс, аккаунт, задержка данных. Действия: «Настройки подключения», «Открыть в … ↗».
- Тулбар: диапазон дат, период (общий с дашбордом), «Обновлено…», «Опросить», «Заметки», «Экспорт» (CSV текущей вкладки, `;`, UTF-8 с BOM), шаг графика Д / Н / М (Н — от 14 дней, М — от 60; недоступные — disabled, при смене периода шаг откатывается на авто).
- Крупные пилюли и график высотой 320px.
- Вкладки с числом строк; таблицы: #, название, метрики; сортировка по клику на заголовок метрики (повторный — обратный порядок, `aria-sort`), шапка липкая, прокрутка внутри (до 560px).
  - GSC: Запросы · Страницы · Страны · Устройства (Клики · Показы · CTR · Позиция) + **Проверка URL** (путь на сайте → статус индекса, последнее сканирование, робот, разрешения, каноническая, Sitemap) + **Sitemap-файлы** (файл, тип, отправлен, прочитан, статус, обнаружено URL).
  - Метрика: Источники · Поисковые системы · Страницы входа · Поисковые фразы («Не определено» — скрытые фразы) · Регионы · Устройства (Визиты · Посетители · Отказы · Глубина · Время на сайте).
  - GA4: Каналы · Страницы входа · Страны · Устройства (Сеансы · Пользователи · Вовлечённость · Время вовлечения).

**Графики**
- Цвета серий — категориальная палитра `--ch-1…--ch-6` (светлые и тёмные ступени проверены валидатором dataviz); сейчас везде одна серия в слоте 1. Одна ось Y.
- SVG рисуется по фактической ширине контейнера (`ResizeObserver`, в т.ч. при открытии ассистента); подписи осей 11px. Шаг на дашборде: до 90 дней — по дням, 12 месяцев — по неделям.
- Наведение: вертикальное перекрестие, точка, тултип с датой (неделей/месяцем), значением, заметками. С клавиатуры: фокус на графике → ←/→, Home/End.

**API**: мониторинги проекта с последним срезом (bands, deltas); интеграции проекта: статус (ok / не подключено / нет доступа + дата), ресурс, аккаунт, время последнего обновления и метод «опросить сейчас»; дневные ряды Метрики (визиты, поисковые визиты, отказы, глубина, время), GA4 (сеансы, Organic Search, вовлечённость, время), GSC (клики, показы, CTR, позиция); разрезы за период для вкладок (источники/каналы, ПС, страницы входа, фразы/запросы, страны/регионы, устройства); GSC URL Inspection и Sitemaps; Вебмастер (API v4): `summary`, `sqi-history`, `search-urls/in-search/history`, `search-urls/events/history`, `indexing/history`, `links/internal/broken/history`, `diagnostics`, `query-analytics/list` (за период и за предыдущий), `search-queries/all/history`; PageSpeed: список проверяемых URL проекта и ежедневные прогоны PSI API по каждому (desktop и mobile) — 4 оценки категорий и метрики LCP, TBT, CLS, FCP, SI, плюс запуск внеочередной проверки; заметки проекта (дата, автор, текст); лог проекта; участники и команды с доступами.
